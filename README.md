# LEGIONFORGE 7.3.5.26124

**Дата сборки документации: 2026-10-21.** Сервер World of Warcraft **Legion 7.3.5, билд клиента 26124**,
настроенный под кастомный клиент (новые расы из BfA и новее: харанир, драктир-визаж, сломленные,
вульпера, врайкул, дворфы Чёрного Железа, култирасцы, таунка, маг'хары, зандалары, тонкий человек).

## Самодостаточность: ничего ставить вручную не нужно

| Что нужно | Откуда берётся |
|---|---|
| MySQL 8.0 | скачивается портативным zip в `tools\mysql` (`scripts\bootstrap_tools.ps1 -MySQL -StartMySQL`), инициализируется и запускается сам |
| 7-Zip | `7zr.exe` с 7-zip.org в `tools\7zip` |
| CMake 3.31.8 | portable zip с GitHub Kitware в `tools\cmake` |
| Boost 1.86 / OpenSSL | prebuilt пакеты в `tools\boost_1_86_0` / `tools\openssl` |
| Компилятор MSVC | Visual Studio 2022 Build Tools через официальный bootstrapper Microsoft (нужен администратор; единственный системный шаг) |
| Программы сервера | собираются из `core\` автоматически (`build_server.bat`), exe кладутся в `server\` |
| Базы данных | `sql\base` (auth/characters) + `Legion_Proyect-DB.7z` (world/hotfixes), импорт только в пустые базы |
| Кастомные патчи | `sql\apply_custom.ps1` (расы клиента 12–21/33, союзные расы, мини-боссы, свитки обликов, улучшение предметов) |

## Порядок запуска

1. **От имени администратора:** `setup.bat`
   — поднимет портативный MySQL, при отсутствии exe соберёт сервер, создаст базы
   `auth/characters/world/hotfixes` и пользователя `trinity`, импортирует дампы
   (только в пустые базы — аккаунты и персонажи не затираются), применит патчи.
2. Игровые данные: положите извлечённые `dbc/maps/vmaps/mmaps` в `server\data`
   (или в `data\` / `client_data\` рядом с `setup.bat` — установщик сам скопирует;
   подойдёт и папка data вашей прежней установки).
3. **`play.bat`** — MySQL → bnetserver (1119) → worldserver (8085/8086) → клиент.
   Exe клиента **не изменяется**: запускается оригинальный `WoW-64.exe`
   (ядро той же линейки, что и кастомный клиент; адрес сервера клиент берёт из
   `WTF\UWow.wtf`: `SET portal "127.0.0.1"`).
4. Первый аккаунт (в консоли запущенного bnetserver):
   `account create admin@legionforge.ru legionforge`, затем
   `account set gmlevel admin@legionforge.ru 3 -1`.

## Что важно знать

* **Вход в мир** требует, чтобы клиент открыл второе соединение на порт **8086**;
  `play.bat` ждёт готовности именно по 8086. Если вход обрывается — нужны последние
  100 строк `server\logs\Server.log` (или `Logs\Server.log`) и окно worldserver.
* **Расы 38–44** в клиентском ChrRaces.db2 — вражеские модели без CharSections,
  персонажа ими создать нельзя; играбельные кастомные расы — **12–21 и 33**
  (патч `sql\custom\105_legionforge_client_races_real_ids.sql` + `111_...`).
* **Модель хараниров (раса 12):** в присланном дампе DB2 у неё display ID
  116539/116687, которых нет в CreatureDisplayInfo.db2, — точную модель даёт
  только оригинальный модельный хотфикс клиента; серверной SQL-заменой это не лечится.
* Файлы клиента (`WoW.exe`, `WoW-64.exe`) сервером не патчатся и не переписываются.

## Структура

`core\` — исходники ядра LegionForge (сборка CMake, C++14, VS2022).
`server\` — конфиги, сертификаты, DLL, сюда ложатся собранные exe и папка `data`.
`sql\` — базовые дампы, кастомные патчи, обновления схем.
`scripts\` — портативные инструменты и сборка.
`setup.bat`, `play.bat`, `build_server.bat`, `stop_server.bat` — точки входа.

## Состояние кастомных изменений: что работает, а что нет

Честно и по пунктам, чтобы не было сюрпризов после часа компиляции.

**Работает в этой сборке**
* Самодостаточная установка: портативные MySQL, 7-Zip, CMake, Boost, OpenSSL скачиваются в `tools\`.
* Автоматическая сборка `worldserver`/`bnetserver`/утилит карт из `core\` (`build_server.bat`).
* `setup.bat` больше не закрывается молча: окно живёт даже при ошибке разбора (`cmd /k`),
  и из него убраны круглые скобки внутри блоков `if (...)`, которые обрывали разбор.
* Импорт баз только в пустые БД, кастомные SQL-патчи LegionForge, ребрендинг и даты 2026-10-21.
* Союзные расы Legion 27–30 (`sql/custom/48`, `49`) — они есть в самом ядре.

**НЕ работает без доработки ядра (важно)**
Новые расы вашего клиента — 12–21 и 33 — в этом ядре не поддерживаются. Проверено прямо
в исходниках этого репозитория:
* `core/src/server/game/Miscellaneous/SharedDefines.h`: перечисление рас заканчивается
  `RACE_LIGHTFORGED_DRAENEI = 30`, далее `MAX_RACES` (то есть 31). Слоты 12–21 закомментированы,
  расы 33 нет вообще.
* Маски рас 32-битные: `constexpr auto RACEMASK_ALL_PLAYABLE = ((1 << (RACE_HUMAN - 1)) | ...)`.
  Раса 33 требует 64-битной маски (`1 << 32`).
* `Player.h`: `IsValidRace(Race) { return ((1 << (Race - 1)) & RACEMASK_ALL_PLAYABLE) != 0; }`.
* `ObjectMgr`: `_playerInfo[MAX_RACES][MAX_CLASSES]`, и строки `playercreateinfo` с `race >= MAX_RACES`
  отбрасываются при старте.

Следствие: `sql/custom/105` и `111` подготавливают данные, но сервер их не примет, пока в ядре
не подняты `MAX_RACES`, маски не переведены в 64 бита и не добавлен реестр «раса → донор/команда».
Это правка 6–8 файлов C++, которую обязательно проверять компиляцией MSVC — в моём окружении
её собрать нельзя, поэтому я не стал класть непроверенный код в архив.

**Не лечится сервером в принципе**
* Модель расы 12 (харанир): в вашем `ChrRaces.db2` у неё display ID 116539/116687, которых нет
  в `CreatureDisplayInfo.db2` того же дампа. Это данные клиента (M2/текстуры), серверным SQL
  они не создаются.
* Выбор класса для новых рас: в вашем `CharBaseInfo.db2` нет ни одной пары «раса 12–21/33 + класс»
  (проверено разбором файла: 149 записей, ни одной для этих рас). Нужен клиентский hotfix
  либо серверная выдача этих строк — это снова правка ядра из пункта выше.

## Исправление MySQL CDN — сборка 2026-10-21c

Oracle удалил MySQL 8.0.40 из основного CDN: старый URL возвращал 404, а `dev.mysql.com/get`
возвращал 403 для PowerShell 5.1. Исправлено:

* основной официальный URL: `mysql-8.0.46-winx64.zip`;
* автоматические официальные fallback: 8.0.45 и 8.0.44;
* `curl.exe --fail --location --retry` с User-Agent, fallback на `Invoke-WebRequest`;
* проверка размера и ZIP-сигнатуры `PK`, чтобы HTML-ошибка не принималась за архив;
* живая GET-проверка всех трёх URL: HTTP 206 (Range), сигнатура `50 4B 03 04`.

Если в `tools\downloads` лежит повреждённый/неполный ZIP, скрипт удалит его и скачает заново.

## Исправление MySQL NativeCommandError — сборка 2026-10-21d

`mysqld --initialize-insecure --console` всегда пишет нормальный прогресс в stderr. Windows PowerShell 5.1
при `$ErrorActionPreference='Stop'` превращал первую строку в исключение `NativeCommandError`, хотя процесс
MySQL работал нормально. Теперь инициализация выполняется через `System.Diagnostics.Process`:

* stdout/stderr читаются асинхронно как обычный лог, а не PowerShell ErrorRecord;
* решение принимается по реальному `ExitCode` и наличию `data\mysql`;
* полный лог сохраняется в `tools\mysql\initialize.log`;
* незавершённый datadir не удаляется — переименовывается в `data.incomplete-ДАТА-ВРЕМЯ`;
* оставшийся от прошлого запуска `mysqld` ожидается до 180 секунд;
* повторный `setup.bat` вызывает `bootstrap_tools.ps1 -MySQL -StartMySQL`, поэтому неполная
  инициализация восстанавливается, даже если `mysql.exe` уже скачан.

Проверка паттерна Process API с `$ErrorActionPreference='Stop'`: нативный процесс написал нормальный stderr,
завершился с кодом 0, исключения нет. Все PS1/BAT проверки проекта — 0 ошибок.

## Учётные данные MySQL

Для портативной базы установщик задаёт именно:

* MySQL administrator/root: `admin@legionforge.ru`
* пароль: `legionforge`
* встроенная учётка `root@localhost` тоже получает пароль `legionforge`.

Worldserver и bnetserver подключаются к MySQL под `admin@legionforge.ru / legionforge`.
Если порт 3306 уже обслуживает другой MySQL с неизвестным паролем root, setup.bat один раз спросит
существующий пароль администратора, создаст/обновит требуемую учётку и дальше перейдёт на неё;
игровые базы при этом не очищаются.
